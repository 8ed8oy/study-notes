# S1 请求生命周期

llm_engine:159 p.join() 优雅关闭

## 1. 状态转移
序列在waiting中等待，被选中直至在 num_cached_tokens + num_scheduled_tokens == num_tokens时进行prefill时，进入running，fifo排列，不断decode，直至eos或者到达max_token,进入finished。(`scheduler.py:129`)当kvcache块不够时发生preempt，序列会从running移出，进入waiting，但lifo(`self.waiting.appendleft(seq)``scheduler.py:79`)。

```
        ① add()                   ② 整个 prompt 都进 KV（prefill 完成）
  新建 ──────────► WAITING ──────────────────────────────────► RUNNING
                     ▲                                             │
                     │ ③ preempt()（KV 块不够，appendleft 插队首）    │ ④ postprocess：
                     └─────────────────────────────────────────────┘     eos 或 num_completion==max_tokens
                                    RUNNING ──────────────────────────► FINISHED
```


## 2. 一次 step 做的三件事

1. ``Scheduler.schedule()` `scheduler.py:25-73``从 waiting 中选出 prefill 或从 running 中选出 decode 的序列，放到 running 中；返回 `(seqs, is_prefill)`，`is_prefill=True` 表示本步是 prefill 批
2. 调用 `model_runner`，在 GPU 中进行一次 forward，得到 token_ids；
3. 对输出调用 `Scheduler.postprocess()` `scheduler.py:81-92`：
   - 更新每个序列的状态（running→finished / running→waiting / waiting→running）；
   - 释放 KV cache 中不再需要的 block；
   - 记录本步刚变为 FINISHED 的序列的输出 token_ids。
