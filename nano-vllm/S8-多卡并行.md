# S8 多卡并行（口述级）

> 建立 2026-10-25。定位：计划 §3 "Tensor parallel 只读不跑" 的落地；**不是第 4 个主资产**。
> 边界：单卡 RTX 3060 12GB，不跑多卡；不碰 CUDA / NCCL 调优（硬规则 3）。预算 3–4h。
> 路径在 `学习轨迹.md` §5；本文是概念 + 口述稿。

## 0. 一句话地图

| 手段 | 切什么 | 通信 | 收益 | 代价 / 边界 |
|---|---|---|---|---|
| TP(Tensor Parallelism) | 层内矩阵/头 | 行并行层 AllReduce，每层 2 次 | 降单卡显存、降延迟 | 通信在关键路径；GEMM 变小；TP ≤8；H_kv 要能被 TP 整除 |
| PP(Pipeline Parallelism) | 层间 | 点对点激活 | 跨机放大模型 | 流水线 bubble；低 batch 利用率低 |
| DP(Data Parallelism) | 复制模型 | 推理无 | 吞吐 | 显存不降，每副本一份 KV |
| EP(Expert Parallelism) | MoE 专家 | AllToAll | 放大 MoE | 路由/负载不均 |
| PD(Prefill-Decode Disaggregation) | 阶段 | KV 传输 | TTFT/TPOT 解耦、独立扩缩 | KV 传输、故障/调度复杂 |

## 1. TP 具体切法（nano-vllm 对照）

- QKV：`QKVParallelLinear`（继承 ColumnParallel），按输出维切，也就是按头切；每卡 `H_q/TP` 个 Q 头、`H_kv/TP` 个 KV 头。
- O：`RowParallelLinear`，按输入维切，forward 里 `dist.all_reduce(y)`（`linear.py:224-259`）。
- MLP：`gate_up` 是 `MergedColumnParallelLinear`（列并行）；`down` 是 RowParallel（行并行）。
- 所以一层 2 次 AllReduce：attention 的 O 之后、MLP 的 down 之后；28 层 = 56 次/forward。
- KV cache：`num_kv_heads = hf_config.num_key_value_heads // world_size`（`model_runner.py:313`）；TP 不能超过 KV 头数，否则分不到头。
- Embedding：词表维切分，查表后 `all_reduce` 合并；LM Head：`dist.gather` 只把 logits 发到 rank 0（`embed_head.py:27-33`），因为只有 rank 0 采样。

## 2. 通信原语

| 原语 | 一句话 | 用在哪 |
|---|---|---|
| AllReduce | 各 rank 部分和相加，所有 rank 拿到完整结果 | RowParallel 输出 |
| AllGather | 各 rank 出一片，拼成完整 | 需要完整张量（如词表并行后的 logits） |
| ReduceScatter | 相加后按 rank 散开 | ZeRO/序列并行；AllReduce = ReduceScatter + AllGather |
| AllToAll | 每个 rank 给每个 rank 发不同数据 | MoE token 路由 |

## 3. 为什么多卡不线性

1. 通信在关键路径：AllReduce 要等所有卡算完；
2. 每卡 GEMM 变小，GPU 利用率下降；
3. TP 超出 NVLink 域走 PCIe/IB，带宽差一个数量级；
4. GQA 下 H_kv 小，TP 太大时部分卡分不到 KV 头。

量级：8k prefill，一次 AllReduce 传 `8192×1024×2B=16MB`；PCIe 25GB/s → 0.64ms，×56≈36ms，和 0.6B 在 A100 上的 prefill 计算（约 31ms）同量级。

## 4. PD 分离

- 问题：prefill 算力密集，decode 访存密集、生命周期长；放一起长 prefill 卡住 decode，TTFT/TPOT 无法独立优化。
- 做法：P 池 prefill → KV 传给 D 池 → D 池 decode；两池独立扩缩。
- 判据：`KV 传输时间 / prefill 计算时间`。
  - 0.6B 每 token 112KB，8k≈900MB；200Gbps（25GB/s）→ 37ms；400Gbps → 18ms。
  - 0.6B 在 A100 上 prefill 8k ≈ 31ms → 小模型传输占比高，不划算；70B 上 prefill 秒级，传输 ~100ms，才划算。
- 成本：KV 传输、P 挂了 KV 丢、P/D 配对与 KV 位置跟踪。

## 5. cache-aware 路由（S4 结论）

- 判据：前缀从第 0 token 起逐块一致，至少满 256；收益 ≈ `256×满块数×(N−1)`，第一个请求不省。
- 边界：长前缀相对收益下降（attention 仍读 cached KV）；缓存会被淘汰；路由造成热点/排队时净亏。
- 网关需要引擎暴露 prefix hash / 命中率。

## 6. 8 道口述题

**1. TP 切哪两个维度？QKV/O/MLP 各怎么切？**
答：TP即tensor parallelism，切层内矩阵和头。QKV按头切，每卡H_q/TP个Q头、H_kv/TP个KV头；O按输入维切，MLP的gate_up是列并行，down是行并行。
**2. 一层几次 AllReduce？为什么？**
答：两次AllReduce，一次在attention的O之后，一次在MLP的down之后。因为这两个操作都是行并行，需要将各卡的部分结果汇总。列并行每卡拿到的是完整输出的不同通道（互不重叠，拼起来就是全的），行并行每卡是同一个输出的不同加数。
**3. 为什么多卡不线性加速？给三个原因。**
答：每张卡GEMM可能变小，GPU利用率下降；AllReduce需要等待所有卡完成计算；卡间通信可能受带宽限制；卡数超过head数，导致部分卡分不到QKV头。
**4. TP、PP、DP 各适合什么？为什么 TP 一般 ≤8？**
答：TP切层内矩阵/头，适合减少单卡显存和降低延迟；PP切层间，适合跨机放大模型；DP复制模型，适合提高吞吐。TP一般≤8是因为一台服务器通常有8张卡，8 卡以内更容易处于同一个高速互联域，但超过8卡时，跨域走 IB/PCIe 带宽差一个量级，导致性能下降。
**5. GQA 下 TP 和 KV 头数有什么关系？**
答：H_kv % TP == 0，TP ≤ H_kv；每卡存 H_kv/TP 个头的 KV。
**6. PD 分离的收益、成本、判据？**
答：Prefill计算密集，Decode访存密集，生命周期长，放一起会互相阻塞。收益是TTFT/TPOT可以独立优化与扩缩容，并对于两者分别选择合适的硬件和策略；成本是kvcache传输、Prefill 实例故障可能导致已生成的 KV 丢失、P/D配对与KV位置跟踪。判据是KV传输时间 / prefill计算时间。
**7. PD 的 KV 传输怎么估？0.6B、8k、200Gbps 是多少？**
答：每token 112KB，8k token就是900MB；200Gbps（25GB/s）传输需要约37ms。但 0.6B 在 A100 上 prefill 8k 只要 31ms（本机 RTX 3060 12GB 68ms），37 > 31，小模型上 PD 不划算
**8. cache-aware 路由什么时候净亏？**
答：前缀过短；缓存被丢弃；路由造成负载过高。**还有最反直觉的一条：长前缀的相对收益会下降**——缓存省的是那 L 个 token 的线性层 + 段内 attention，省不掉后缀对全长的 attention，所以收益按 L/P（线性层主导）到 (L/P)²（attention 主导）缩水，看的是命中占比，不是前缀绝对长度。

## 7. 90 秒话术

"多卡并行先看切什么：TP 切层内矩阵，每层两次 AllReduce；PP 切层间，点对点传激活；DP 复制模型换吞吐。TP 不线性的核心是通信在关键路径、每卡 GEMM 变小、跨 NVLink 域带宽骤降，所以一般 ≤8。再往上，PD 分离把 prefill 和 decode 放两个池，收益是 TTFT/TPOT 解耦和独立扩缩，代价是 KV 传输——0.6B 每 token 112KB，8k 就是 900MB，200Gbps 要 37ms，所以要看 KV 传输 / prefill 计算的比值。网关侧的 cache-aware 路由也是同一个思路：省 prefill 的前提是前缀 ≥256 且逐块一致，否则收益为 0，还会换来热点。"
