# 计网「一屏实验卡」：格式与清单

> 来源：`0_规划/大学计划…§2.3` 与 `§6.2`——实验产出用"一屏实验卡"替代正式报告，可并入周小结或章节笔记。
> 目的：一张卡 = 一个能被追问的问题 + 一套能复现的操作 + 一条能背下来的结论。**不是实验报告**，控制在一屏（约 60–100 行）。

## 格式（五段必须齐）

| 段 | 写什么 | 硬要求 |
|---|---|---|
| ① 问题 | 这一卡要解释的**一个**问题 | 一句话，指向具体机制 |
| ② 操作 | 实际敲的命令（可复制） | 带参数，注明在哪个接口/哪台机器 |
| ③ 观察 | **原始输出**（贴原文） | 保留时间戳/行号/Flags；不要只写"失败了" |
| ④ 解释 | 用课程机制解释看到的现象 | 每个观察点对应一条原理 |
| ⑤ 结论 | 一句话结论 + 可迁移动作 | 结论要能脱离本实验复用 |
| 附加 | **实验前的预测**（可证伪） | 写完预测再跑，防止事后解释 |

其它纪律：
- 数字必须是自己跑出来的，AI 只做整理与追问；
- 一卡一问题，别把 DNS 和 TLS 混在一张卡里；
- 卡尾留"常见追问"3–4 条，面试前直接拿来自测。

## 服务端侧扩展（2026-10-22 补；不新建文件）

> 原清单是客户端视角（握手 / 复用 / 证书）。投递前必须补服务端侧，否则网关面试里"连接数为什么涨、请求为什么排队"答不上。做法：**不新开卡，直接在上面两张卡里加一节 `## 服务端侧`**。

| 扩展项 | 并入哪张卡 | 状态 | 要观测什么 |
|---|---|---|---|
| `TIME_WAIT` / `CLOSE_WAIT` 堆积 | [实验卡-TCP握手与SYN黑洞](计网自顶而下/实验卡-TCP握手与SYN黑洞.md) | ⬜ | `ss -tan state time-wait`、`ss -s`；区分"主动关方堆积"与"应用没关 fd" |
| accept 队列与 backlog | [实验卡-TCP握手与SYN黑洞](计网自顶而下/实验卡-TCP握手与SYN黑洞.md) | ⬜ | `ss -lnt` 的 Recv-Q 是否持续 >0；`netstat -s` 里 listen overflows；区分"丢包"与"accept 太慢" |
| keep-alive 与连接池失配 | [实验卡-HTTP-keepalive与队头阻塞](计网自顶而下/实验卡-HTTP-keepalive与队头阻塞.md) | ⬜ | 客户端复用连接、服务端 `IdleTimeout` 先关 → 复用到半关连接（网关必问） |
| 反向代理超时链路 | [实验卡-HTTP-keepalive与队头阻塞](计网自顶而下/实验卡-HTTP-keepalive与队头阻塞.md) | ⬜ 选做 | 连接 / 读 / 写超时分别对应链路的哪一段 |

复现成本：本机 Go 服务 + `wrk` / `ab` / `curl` 就能造，不需要新环境。
