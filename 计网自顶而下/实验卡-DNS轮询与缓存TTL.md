## 2. 问题（我要解释什么）

同一个域名连续查询，返回的地址顺序/集合是否变化？TTL 有多长？"缓存住了坏答案"和"权威记录本身有坏地址"怎么区分？

## 3. 预测（先写再跑）

> 如果这是轮询 DNS，那么连续多次 `dig` 应当返回**同一组地址、不同顺序**（或不同子集），且 TTL 会从设定值递减；用不同公共 resolver 查询，TTL 应回到权威值附近。

## 4. 操作（命令）

```bash
# 观察一：连续查询，看顺序/集合是否变化
for i in $(seq 1 8); do dig +short example-domain A | tr '\n' ' '; echo; done

# 观察二：看 TTL（+noall +answer 保留 TTL 列）
dig example-domain A +noall +answer

# 观察三：追到权威 NS，区分"权威给的"和"本地缓存的"
dig +trace example-domain A
dig @1.1.1.1 example-domain A +noall +answer
dig @8.8.8.8 example-domain A +noall +answer

# 观察四：如果本机跑了代理/本地解析器，对比走代理与绕过代理的解析结果
#   （fake-ip 会返回 198.18.x.x 合成地址！这是区分"权威坏"与"本地状态过期"的关键）
dig @127.0.0.1 example-domain A +short

# 观察五：确认地址归属（云厂商/地域），解释"为什么这些 IP 会死"
whois <IP> | head -20
```

## 6. 解释（机制）

1. **DNS 是名字到地址的映射，不提供健康检查**：轮询 DNS 只做"分发 + 轮换顺序"，不会摘除不健康后端（能摘除的是 L4/L7 负载均衡器的健康检查）。
2. **TTL 决定故障窗口**：权威 TTL=600s 时，坏答案会被各级缓存 600 秒；"十几分钟自愈"就是缓存到期的现象。缓存可能持久化在本地（如代理的 `cache.db`），重启进程也不一定清掉。
3. **fake-ip**：TUN 代理会让 DNS 返回 `198.18.0.0/16` 的合成地址，代理靠自己的映射反查域名——**这是本地引入的状态**，映射过期或丢失时会连接到"路由不到"的合成地址，与权威记录无关。
4. **区分判据**：换公共 resolver 也返回坏地址 ⇒ 权威记录问题；只有本地/代理解析出坏地址 ⇒ 本地缓存或 fake-ip 状态问题。

## 8. 常见追问（预演）

- TTL 到期后一定会拿到好地址吗？——不一定，取决于权威当时的记录集合。
- 为什么不能把好地址写进 `/etc/hosts` 钉死？——入口集合是动态的，钉的地址会变死（W40&41 已实际踩到）。
- 递归解析器在这条链路里扮演什么角色？——逐级查询并缓存，本地看到的往往是"某级缓存"的答案。
- DNS 查询本身走什么传输层？——通常 UDP/53（响应大或带 DNSSEC 时截断后转 TCP），这也是"DNS 能通但 TCP 不通"要分开测的原因。
