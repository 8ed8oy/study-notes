### 真正的元凶：`libinput` 压力阈值 Bug

既然内核已经支持，为什么还是只能单指点击、不能移动？
根据开源社区对这款机器的调试反馈：这块 Goodix 触控板硬件上报的压力参数存在严重偏差——**它默认的按压压力阈值（Press-down threshold）高于了 Linux 系统自带的手掌防误触（Palm detection）阈值**。

结果就是：底层的 6.17 内核确实收到了你的滑动和多指信号，但在把信号上报给用户态的 `libinput` 库时，系统判定“这么大的压力，肯定是整个手掌压在上面了”，于是触发了防误触机制，**把你的正常移动和多指操作全部作为误触丢弃了**。

---

### 最终解决办法：应用 Quirks 规则（3 步搞定）

既然内核已经 OK，你只需要卸载冲突的第三方驱动，并写个规则告诉 `libinput` 直接屏蔽掉这块触控板的压力传感器即可。

#### 第 1 步：卸载第三方驱动，恢复内核原生状态
在你之前编译 `goodix-gt7868q-linux-driver` 的源码目录下打开终端，清理掉你刚装的驱动：
```bash
sudo make uninstall-dkms
```
*(如果你不是通过 dkms 安装的，请执行 `sudo rmmod goodix_gt7868q` 或删除对应的 `.ko` 文件，并移除任何可能添加的 blacklist 文件。)*

#### 第 2 步：写入 libinput Quirks 规则（屏蔽压力检测）
这是最关键的一步。在终端中创建一个自定义的 quirks 文件，让系统忽略这台机器触控板的错误压力值：
```bash
sudo nano /usr/share/libinput/60-custom-thinkbook.quirks
```
将以下内容粘贴进去：

```ini
[Lenovo Thinkbook 2024 Goodix Touchpad]
MatchName=*Goodix*
MatchUdevType=touchpad
MatchDMIModalias=dmi:*bvnLENOVO:*
AttrEventCode=-ABS_MT_PRESSURE;-ABS_PRESSURE;
```
> **核心原理：** `AttrEventCode=-ABS_MT_PRESSURE;-ABS_PRESSURE;` 这行代码的作用是直接粗暴地关闭该触控板的压力检测。彻底绕过压力防误触拦截后，单纯的位置识别就会接管，光标和多指手势立刻就能复活。

保存并退出（在 nano 中按 `Ctrl+O`，回车确认，然后 `Ctrl+X` 退出）。

#### 第 3 步：更新硬件数据库并生效
在终端执行以下命令更新系统硬件数据库：
```bash
sudo systemd-hwdb update
sudo udevadm trigger
```
为了确保 `libinput` 完全重新加载这些规则，**请重启一次电脑**。重启后，配合你现有的 6.17 内核，原生的多指手势、双指滚动等功能应该就能完美使用了。
